# LLM 글쓰기 잡기술
**Date:** 9시간 전
**Category:** 스냅
**Original URL:** https://blog.naver.com/xpfkwh56/224410257194
---

1. LLM 의 도움을 받아서

생성한 글이 마음에 안 든다

​

어떻게 해결 하는 것이 가장 좋을까?

​

보통 많이 하는 방법은 **'그 부분'** 만

고쳐달라고 하는 것이다

​

이유는, 인간에게는 이런 지시가

**'당연히'** 맥락을 함의하기 때문인데,

​

LLM 의 입장에서 지시를 받으면

무지성으로 딱 저 내용만 이해를 한다

​

예를 들어보자,

​

QWEN 모델이 LLM 생성 과정에 있어

가장 많이 실수를 나타내는 부분이

​

**인칭에 있어서의 성별 부분** 이다

​

여자를 그는 이라고 표현하거나,

단수를 그들은 이라고 기재 한다

​

**스크립트 돌리면 되잖음?**

​

사건의 주인공이 여자일 때는,

모든 그를 그녀로 치환

​

이런 식으로 하면

​

그, 그녀 가 혼용된 문장들이

연이어 나올 때 작살 나게 된다

​

2. **'교과서적'** 인 방법은 다음과 같다

​

수정할 부분이 나오면,

반드시 통째로 다시 쓴다

​

**\* 아니면 사람이 직접 수정**

​

통째로 다시 쓴 다음, 글을 나누어서

​

병렬로 리딩을 시킨 다음에

오케스트레이션 을 굴린다

​

즉, 1문단/2문단/3문단

1/2문단 2/3문단

123 문단을 읽게 돌리고,

​

겹치는 부분들을 추출한 다음,

의미에 맞게 체크해서 정보 단위로

바꿀 부분을 전파 시키는 것이다

​

3. 문제는 이렇게 하면 **'비싸다'**

​

프론티어에선 거의 불가능 한데,

​

**\* 부팅 토큰 감안하면 답이 없음**

**​**

이럴 때 할 수 있는 요망한 트릭이 있다

​

바로 greb 기능을 사용해서,

바꿀 토큰 단위를 선별한 다음에

​

해당하는 문장의 앞뒤, 문단의 앞뒤만

프론티어의 세련된 읽기를 쓰는 것이다

​

만약 그냥 edit 을 시키면,

llm 은 글 전체를 읽고 수정하는데

​

이 경우, 동일한 어텐션이 정렬된 경우

자신의 오류를 찾지 못할 가능성이 높고

​

교차 검증을 시키는 경우, 부분 문장으론

전체 문장의 관련성을 연결 지어서

연산할 수 없을 확률이 높기 때문에,

​

선 greb 후 edit 을 쓰는 것이 효과적 임

​

4. 주의할 점은, 이 역시 **휴리스틱** 이라

​

정말 개빡 자동화 돌리는 것 아닌 이상,

사람이 읽고 수정 하는 것이 경제적이고

​

정 사람이 읽기 버거운 부분이 있다면

청킹 단위로 잘라 병렬 돌리는 것이 답임
