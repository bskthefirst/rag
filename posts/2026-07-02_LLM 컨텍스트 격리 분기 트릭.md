# LLM 컨텍스트 격리 분기 트릭
**Date:** 2026. 7. 2. 2:18
**Category:** 일기장
**Original URL:** https://blog.naver.com/xpfkwh56/224333644257
---

1. LLM 로 발생하는 토큰은 크게 4 종류임

거기서 가장 무서운 것이 **캐시****리드** 임

​

이유는 이게 계속 제곱해서 쌓이기 때문

​

**\*** **본질적으로 히스토리 재처리량이 N^2**

​

가랑비에 옷 젖는다고 통념과 달리

안심하고 생각 않는데 제일 위험함

​

다른 많은 사람들도 똑똑한 여러 가지

해결책을 만들어서 제안하지만, 로컬에서

개인이 쓰기에는 부적절한 경우들도 많고

​

셋업 난이도나, 여러 측면에서 나쁠 수 있음

​

그래서 최근 알아낸 방법 하나를 공유함

​

1) 트렌스크립트 로그 스냅을 찍음

로그 스냅은 순수 CPU 자원만 써서 0원

​

2) 그리고 여기서 **'분기'** 를 잡음

​

대부분의 LLM 은 의미 기반 독해가 좋아서

주제가 변경되었다 또는 화제가 바뀌었다

같은 것들을 체크할 수 있는데, 넛지 처리함

​

3) 그래서 **'분기'** 가 나뉘면,

트렌스크립트 자체를 백업해서

​

A 분기, B 분기로 분류한 다음

필요한 만큼 대화가 끝나고 나면

​

클로즈 하고 다시 분기로 가면 됨

​

2. 예시를 들자면 다음과 같음

​

user : 오늘 뭐 먹지?

llm : 라면

​

user : 라면 어떻게 끓이지?

llm : (라면 끓이는 법 알려줌)

​

user : 떡 넣으면 더 맛있나?

llm : (어쩌고 저쩌고)

​

user : 내일 비 오나?

llm : (어쩌고 저쩌고)

​

이렇게 하면, 토큰 효율 비효율

​

**그러므로,**

​

user : 오늘 뭐 먹지?

llm : 라면 (뭐 먹지 물어봤다 → 분기)

​

user : 라면 어떻게 끓이지?

llm : (라면 끓이는 법 알려줌)

​

user : 라면 말고, 치킨 먹을까

llm : (라면 분기로 돌아감) 치킨 좋지

​

이렇게 하면, 라면 화제로 이야기한

컨텍스트 자체는 말끔히 사라지고,

​

각 분기 마다 세션이 나뉘어지기 때문에

편하게 티키타카 해도 컨텍스트 오염 적음

​

3. 논문엔 이게 다 산발적으로 흩어져 있는데

conversation tree 개념으로 위처럼

조립해서 쓰면 실용성 있게 써먹을 수 있음

​

캐시리드는 프론티어 모델에서도 제일 싸고,

로컬 토큰 굴릴 때도 컴퓨팅 압박 없는데요?

​

5m 단위 세션 쌓인 곳에

**'안녕'** 하나 치면

재앙이 일어납니다

​

그걸 해결하려면 매번 새로운 세션 켜야 되는데,

제가 말한 아이디어 쓰면 그런 문제가 해결 됨

​

그냥 이전 분기로 돌아가면 되니까

​

그리고 각 분기마다 쌓인

트렌스크립트는 하드에 남으니,

​

그 하드에 있는 내용만 꺼내오면 됨

​
