# MAS 로 사기치는 사람들
**Date:** 23시간 전
**Category:** 일기장
**Original URL:** https://blog.naver.com/xpfkwh56/224376894173
---

**1. MAS 가 뭐임?**

​

멀티 에이전트 시스템 임

​

인공지능끼리 서로 대화를 하거나,

팀을 이루어서 작업하는 것을 말함

​

2. 뉴스야 애초에 유료 기사니까,

​

그런갑다 하는데 최근에 눈팅 하다

이거로 묘한 장사하는 분들이 있는 듯

​

먼저 MAS 는 내가 알기론

**'작업 수행'** 을 올리는 것이 아님

​

그냥 한정된 자원 내에서 더 효율적으로

어디에 토큰을 집약하냐 하다 나온 거고,

​

100개의 에이전트를 굴려가지고,

자동으로 어쩌고 저쩌고 이런 얘기는

​

**'그 사람'** 한테는 그럴 수 있어도,

실제로는 잘 안 돌아갈 확률이 큼

​

3. 먼저, 단일 모델을 사용하고 있을 때

상호 모델의 교차 검증 신뢰성이 나쁨

​

**무슨 말이냐?**

​

내가 제미나이 쓰고 있는 상태에서,

제미나이 2개 열어놓고 서로가 서로를

확인하라고 하면 **그게 그거** 된다는 것

​

**\* 여러 모델을 섞으면 되겠네?**

**​**

**같은 모델이 같은 언어를 쓰냐,**

**같게 학습이 됐냐를 알 수 없으니**

**​**

**무작정 모델끼리 연결 시켜놓으면**

**병신이 병신을 가르치는 상황 나옴**

**​**

이걸 해결하려면, 작업 과제에 있어서

서로 다른 관점을 갖는 모델을 명세하고,

​

그걸 **'결정론적 단위'** 에서

게이트로 묶어서 관리해야 하는데

​

안타깝게도 아주 오랜 시간이 걸리고,

개발 지식이 아예 없으면 솔찌 **불가능** 함

​

**\* AI 는 코딩을 능란하게 잘 하는 듯 하지만,**

**사람이면 5줄로 끝낼 작업을 50줄, 심하면**

**100줄, 200줄로 늘리면서 돌아가지도 않음**

**​**

**검증 게이트는 대부분 사람이 짜야 될 것임**

**​**

4. 그럼 아예 쓸모가 없냐?

​

**그건 아님**

​

MECE 하게 구획을 잘 나눠 가지고,

특정 작업에서 특정 에이전트가 정확히

자신의 권한 영역만 처리하게 하면 됨

​

근데 그걸 하려면, 작업 내에서

에이전트가 '담당하는' 분야가 뭔지,

​

문제가 생길 때, 화해는 어떻게 할 건지?

거버넌스는 어떻게 짤 것인지?

​

엣지 케이스 발생 했을 때,

그냥 사람 호출로 다 떼울 건지 아니면

자발적으로 AI 끼리 협업을 하게 할 건지,

​

협업을 한다면 그 프로토콜은 어떤 건지,

같은 것들을 **전부** 명세로 남겨내야만 함

​

남긴다고 끝도 아니고,

​

AI 와 AI 가 서로 **'대화'** 를 하면서

회신하는 것 자체도 오버헤드 라서,

​

아마? 대부분은 산출물로 계약하고,

​

통신이 가능하되, 그게 주력이 아니고

​

기계적으로 작동하되 규약 외의 경우에

제한적으로 규율에 맞게 할 확률이 높음

​

5. 어떤 분의 경우, 80개가 넘는

에이전트를 팀으로 꾸려가지고

​

운영 하고 계신다는데, **솔직한 말로 ,,**

​

지피티한테, **'너는 ~전문가야'**

라고 한 줄 쓰고 자기는 현존하는

​

전문직 AI 로 다 대체했다 라고

말하는 것 보는 느낌이랑 똑같음

​

1) 로컬을 쓰는지, 프론티어를 쓰는지,

섞어서 쓰는지, 뭘 어찌 하는진 몰라도

​

**컨텍스트 압축 생길 때,**

**작업 일관성 어떻게 수행함?**

**​**

**압축 없으면 로그 짤릴 때 다 버림?**

**​**

2) AI 끼리 서로 협업 시킬 때,

격리/독립 환경 개빡으로 안 잡으면

​

서로 편향 걸려서 실질적으론

에이전트 구분도 안 되는데,

​

**\* 100개든, 1000개든 나눠놨어도**

**작업이 지속되면서 1개로 수렴함**

​

이걸 막을 수 있는 방법이 각 작업자별로

폴더 만들어서 계약 관리 단위를

디스크로 하는 것 외에 **내가 알기론** 없음

​

딱 10시간만 돌려도, 토큰 캐시가

**최소** 십억 단위로 넘어가게 될 건데,

​

이걸 api 로 결제해서 쓰고 있다?

20X 쓰고 있어도 3일이면 녹을텐데?

​

로컬로 하고 있다?

​

SSD로 한 100테라?

있으면 또 모르겠음

​

사람이면, 저번 주에 우리 했던 작업에

뭐 있었는데 그거 이슈 뭐 였지? 하면

​

아, 그거요 하고 **'떠올리기라도'** 하는데

​

AI 는 그거 하나 찾으려면

정말 촘촘하게 개발하지 않은 한,

​

LLM 이 **전수 통독해야** 맥락 복원함

​

특이한 환경 아니면 많이

**읽어봤자 20kb** 남짓이고,

​

그나마도 최적화로 피를 토하실건데,

​

비일관 단일 작업에 에이전트 쓸거면

차라리 서브에이전트를 부른다거나,

​

1회성 스크립트 양산해서 해결하지

파이프 라인으로 짤 이유가 뭔지 몰겠음

​

6. 딸깍 으로 뭐도 되고 뭐도 된다,

​

라고 하는 것의 **'열에 아홉'** 쯤은 사기고

그게 가능하려면 본인이 **차력쇼** 해야 됨

​

요즘엔 AX 라느니, 그래프 엔지니어링이라느니

또 먼 희한한 주제로 말씀하는 분들도 보이든데

**​**

**개발이랑, ai 활용이 매우 유사한 지점이 있음**

​

1) 내가 만든 코드는 내가 제일 잘 안다,

​

즉 특정 프로젝트를 **'오래'** 붙들고 있는 놈이

특이한 경우 아니면 그걸 **제일 잘 하는 애** 다

​

2) 특정 프로젝트를 **'오래, 많이'** 붙들어봤던

경험이 있는 애가, 마침 운이 좋게도 예전에

​

어디서 한 번 경험했던 시행착오/알고리즘 등

​

자기가 **'지 돈, 지 시간, 지 노력'** 을 써가지고

얻은 역량이 있으면 그게 이 바닥 **'전문성'** 같음

​

**\* 우리 오라비들은 현업 개발자들이고,**

**10년 넘게 개발 했는데 내가 최근에 만든**

**코드 보여줘도 그거 보자마자 이해 못 함**

**​**

즉, 뭘 배우고 한다고 해서

​

그거만 들고 좔좔 벽 나올 때마다

**다 뚫고 다니는** 이게 걍 불가능 함
