**7. 실전 A**

​

터미널을 **'2개'** 이상 열 수 있음

​

1) 하이큐, 소넷, 오퍼스 3개를 열고

하이큐랑 소넷은 추론 미디움 걸고,

오퍼스는 추론 max 잡은 다음에

각 목적에 맞게 업무를 지시하면 됨

​

**2) 하이큐**

​

매우 단순한 위임 작업

​

바탕화면에 파일 뭐 있어?

인터넷에 이거 검색해

​

**3) 소넷**

​

적당히 그냥 무난히 쓸만한 곳

​

**4) 오퍼스**

**​**

긴 컨텍스트, 아키텍쳐 설계,

답이 없는 문제를 풀어야 될 때

​

터미널 3개를 나눠서 운용할 수 있음

​

일단 소넷을 중심으로 하고,

​

오퍼스/하이큐로 나눠서

수작업하면 토큰 효율 급증함

​

**8. 실전 B**

​

각 폴더마다 클로드 메모리를

**나눠서** 관리하는 것이 가능

​

예를 들어, 폴더 x 가 있고

폴더 y 가 있을 때

​

폴더 x 에서 구동되는 클로드랑

폴더 y 에서 구동되는 클로드가

​

서로 다른 메모리, 컨텍스트를

가진 상태로 업무를 하게끔 가능

​

**9. 쥰내 귀찮은데, 웹클 쓰면 될 것을**

**왜 굳이 CLI 로 넘어가야 되는 것이죠?**

​

1) 웹클로드는 대화창이 길어지면

익스플로러 이슈 때문에 대화가 씹힘

​

텍스트 섹션 하나가 날아갈 수 있는데

CLI 에서는 구조적으로 그런 일이 없음

​

2) 웹클로드는 **'사용환경'** 을 알 수 없음

​

근데 CLI 클로드는 사용자가 보고 있는

환경을 그대로 보면서 조작, 제어 가능

​

3) 웹클로드는 ctx를 확인할 수 없음,

그래서 compact 언제 터질지 모르는데

CLI 에서 쓰면 그걸 제어할 수 있어짐

​

4) 웹클로드는 쓰다가 멈추면 하이방임

​

근데 CLI 클로드는 **'반로컬'** 이라서,

지속 가능한 프로젝트를 이룰 수 있음

​

그리고 CLI 클로드를 사용하면서

구현된 영역은 **'의외로 아주 많은'**

영역을 **'로컬'** 로 치환하는 것이 가능

​

즉, **'설계'** 만 오퍼스를 맡겨서 하고

​

명세를 기반으로 omnicoder 9b 양자화를

서빙해서 돌리면 **'공짜 토큰'** 을 쓸 수 있음

​

마린으로 서빙하면, qwen 3.5 9B 모델이

멀티모달 옵션 들고 **t/s 200 까지** 터지는데

​

**\* 5090 이라고 다 터지는 것 아님**

**AWQ + 마린 + vLLM 네이티브로 해야**

**​**

**Vram 24gb 언더에서 에이전트 루프를**

**자동으로 돌리는 것이 가능하다는 소리임**

​

웹클로드로는 오케스트레이션 자체가 불가능하고,

쌩 로컬로 한다고 해도 개인역량이 매우 필요한데

​

아예 맨땅에서 오케스트레이션 하는 것보다,

오퍼스/소넷/하이큐 체제로 익숙해진 이후,

​

단일 폴더에서 데이터 흐름을 구축하고,

다중 폴더에서 프로젝트 관리로 운영하다가

​

git 이나 VS, 또는 옵시디언 연동을 쓴 이후,

하나씩 로컬로 대체하면 더 쉽게 할 수 있음

​

**\* 더 쉽다는 것이지, 쉬운 것은 아님**

​

그리고 물론 쓰기 나름이겠지만,

​

**'단일 코딩 성능'** 은 GPT 프로가

클로드보다 더 높은 것은 사실임

​

**\* 하드캡 때문에 다 못 뽑을 뿐**

​

그래서 CLI 2개를 연결해서,

긴 컨텍스트로 어렵게 하는 작업은

​

GPT 프로 API 호출로 처리하고,

​

**\* 최고급 코딩 전문 기술자 지위**

​

일을 나눠서 하면 코드 품질 측면이나,

확장성, 유지보수 문제를 해결할 수 있음

​

**10. 클로드 코딩의 한계와 단점**

​

1) 프로젝트 관리가 안 됨

​

그래서 CLI 로컬로 넘어가서,

컨텍스트를 먹여주면서 해야 됨

​

바이브 코딩의 가장 큰 단점은,

​

**'하루'** 만에 만들 수는 있어도

**1년 걸리는 것은** 못 만든단 것임

​

2) 홈페이지 구현에서의 문제

​

UI/UX 감각이 너무 **양키센스**​ 임

​

**\* 만들다보면 다 비슷비슷하고,**

**어째 AI 냄새 나는 UI 가 나옴**

**​**

CLI 클로드한테, 알리바바에서 만든

OCR 이나 디자이너 웹도구들 물려주면

​

파인튜닝 없어도 디자인 성능이 향상되고,

여기에 데이터셋 입혀서 경량 로컬 모델을

​

**'신입 디자이너'** 로 사용하면,

클로드를 더 유용하게 쓸 수 있음

​

**11. 원 모아 띵쓰**

​

윈도우 네이티브로 굴렸을 때,

개발자들한테는 약간 영어에 가까워서,

할 줄 알면 내가 할 수 있는 범위가 커짐
