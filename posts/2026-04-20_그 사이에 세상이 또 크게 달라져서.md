1. 예전엔 맨땅 로컬부터 박고 봐야 했는데,

​

지금은 프론티어 모델 굴렸던 워크플로우를

바탕으로 로컬로 전환하는 것 또한 방법임

​

**예전엔 왜 그랬음?**

​

프론티어 모델이 API 전환 하는 것 아니면

내장 기능으로 오픈소스 옵션을 쓸 수 없었음

​

근데 서비스 경쟁이 심해져서 그런지,

아니면 기술이 더 좋아져서 그런 것인지

​

지금은 오픈소스 바닥에서 촉망 받는다,

유망하다 싶으면 그거 고스란히 가져다가

적당히 먹기 좋게 가공해주는 형태로 바뀜

​

마치, 스팀 게임에서 인기 있는 모드 나오면

정식으로 편입되는 그런 느낌으로 되고 있음

​

**2. 클로드 기준으로 시도해 봄직한 것들**

​

꼭 클로드만 되는 것은 아니지만,

​

가격이 문제지 **편의성** 이 적어도 지금

기준으로는 다른 모델 대비 너무 좋음

​

**\* 다만, 지맘대로 닫았다 열었다 하는 서버**

**이유를 알 수 없는 성능 저하 같은 이슈는**

**어쩔 수 없이 감안하고 써야 될 부분이 존재**

​

**지금은 그냥 저냥 참고 쓸 수 있을 정도지만,**

**개인적으론 오래 가진 않을 것 같긴 합니다**

​

**1) 터미널 그 자체**

​

왜 자꾸 일단 터미널을 쓰라고 하냐면,

​

처음에는 조금 어색할 수가 있는데

CLI 로 넘어가는 순간, 제약이 없어짐

​

내가 보는 화면 스샷 찍을 수도 있고,

키보드로 직접 타이핑 시킬 수도 있고,

​

마우스 알아서 움직여서

버튼 누르게 할 수도 있고,

​

특정 동작을 반복하게 시킬 수도 있고,

​

컴퓨터에 있는 특정 폴더, 특정 파일 읽어라

수정해라, 삭제해라, 생성해라 등등

​

그냥 인간이 내 컴퓨터를 조작하게 하는

수준의 작업을 터미널로 전부 할 수 있는데,

​

이게 써보면 **매우 신박하게** 느껴짐

​

거기에 클로드 자체 내장 기능 들만

따지고 들어가도 책 한 권 분량은 가뿐히

나올 정도로 별의 별 온갖 것들이 있어서

​

그거만 하나씩 익혀도, 배울 자료론 충분함

​

**\* Claude for Chrome 의 경우,**

**순수 시각 기반 UI 조작까지 구현**

**​**

**2) 멀티 에이전트 시스템**

​

나는 이거 하나만 써먹을 생각을 해두,

클로드로 220불 쓰는 것이 안 아깝다고 봄

​

**멀티 에이전트 시스템이 뭔데?**

​

인공지능이랑 인공지능이 서로

실시간, 준실시간 커뮤니케이션 하면서

지시한 작업을 하도록 지시하는 것임

​

아주 간단하게 구현하는 법 알려드림

​

**\* 쉽지만 매우 원시적인 접근**

**​**

터미널 2개를 열고,

넉넉히 1분마다 풀링하게 함

​

A 터미널과 B 터미널이 있다고 할 때,

간단히 첫 물꼬만 틔우고

​

A 터미널은 B 터미널 스샷을 찍고

거기에 있는 텍스트를 읽고 답하게 함

​

B 터미널도 똑같이 A 터미널 스샷 찍고

거기 있는 텍스트를 읽고 답하게 함

​

답은 어떻게? 그냥 set key 로

직접 입력해서 쓰라고 하면 됨

​

그럼 인공지능끼리 서로 대화하게 됨

​

**\* 토큰은 폭풍처럼 녹아내립니다**

​

복수의 인공지능 모델을 서로 연결 시켜서,

협업하게 할 수 있다는 발상이 나오게 되면

​

내가 터미널 X 에서 클로드랑 대화할 때,

지금 터미널 X 클로드가 규약을 위반했나?

​

같은 것도 실시간으로 체크하게 할 수 있음

​

**\* 품은 많이 들어감**

​

2개의 클로드를 켠 다음에,

1개의 클로드와 대화하는 내용을

​

계속 실시간으로 복붙 시켜서,

다른 클로드가 그 내용을 읽고

​

어, 이거 틀렸어 저거 틀렸어

이렇게 답변해야겠어 같은 훈수를

두고 피드백 시키는 것도 가능한데

​

이러면 사용자 경험 퀄리티가 좋아짐

​

단, 에이전트 루프는 **'겁나 비쌈'**

​

그래서 대충 맛 좀 봤다 싶으면

저렴한 모델로 바꿔 써보셔야 되고,

​

tool calling 비롯해서, 클로드에 있는

깔끔한 내장 기능들을 내가 열심히 깎아

커스텀해서 돌릴 각오를 해야 쓸 수 있음

​

**뭐 그래봤자 한 몇 십 아닌가요?**

​

에이전트 루프 돌려서, 작업 완성도 높게

잡고 토큰 썼다가 월 토큰값 수천만원 에서

수억 나온 사람이 한 둘이 아님니다맠ㅋㅋ

​

**\* 토큰값 1억 나올 때, 20%만 절감하게끔**

**설계 교정해도 그 사람은 자기 월급 다 뽑음**

​

**3) 실시간 메모리 관리 및 특화 모델 구분**

​

웹 클로드는 단일 메모리 구분 밖에 안 됨

​

근데 터미널 클로드는 기본적으로

세션 단위 구분이 가능하기 때문에,

​

내가 A 세션, B 세션 별로 메모리를 전부

다르게 지정해서 사용하는 것이 가능함

​

여기서 더 놀라운 것을 해볼 수도 있는데,

​

옵시디언에 심볼릭 링크 걸어서,

시스템 프롬프트와 메모리를 쓰게 하고

​

CTX 노트를 만들어서 특정 키워드 마다

그 노트 내용을 읽고 답변을 하도록 시키면,

​

웹 클로드로는 **'물리적 특정 시간'** 안에만

학습할 수 있는 개인별 데이터를 터미널에선

**실시간으로 뽑아서** 분석, 적용하는 것이 됨

​

4월 20일 오전 11시에 대화했던 내용이 있다?

​

거기서 자주 나온 키워드가 뭐고, 무슨 주제로

말을 했고, 사용자 선호가 어떤 형태로 보였다?

​

그러니까 유사한 상황일 때, 그걸 반영해서

이렇게 응답해야 된다 같은 것을 시킬 수 있거나

​

사용자와 대화하면서 직접 옵시디언 권한을 갖고

자기가 자기 시스템 프롬프트나, 메모리를 수정,

생성, 삭제 하는 등의 작업도 시키게 할 수 있음

​

단, 그걸 **'할 수'** 있다는 것이지

**'제대로 작동한다는 보장'** 은 없기 때문에

​

**\* 메모리에는 있어도 안 읽을 수도 있고,**

**명세가 있어도 무시하고 휴리스틱 할 수도 있고**

**설계로 해결 안 되는 깡성능은 타협을 하거나,**

**아니면 더 열심히 깎는 것 외에는 방법이 없음**

​

비교적 꼼꼼히 만들어서 써야 될 필요 있음

​
